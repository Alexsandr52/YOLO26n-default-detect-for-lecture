# YOLO26: демонстрация для лекции

Простой сервис детекции объектов на изображениях и видео с предобученной моделью YOLO26n. Рассчитан на CPU. Для каждого файла создаётся отдельное задание; изображения и видео обрабатываются разными процессами. Параллельные запросы могут ждать в очереди, а скорость зависит от сервера. Результат видео не содержит звук.

## Запуск

На сервере с Docker и Docker Compose:

```bash
cp .env.example .env
docker compose up --build -d
```

Сайт: `http://АДРЕС_СЕРВЕРА:8000`. Логи: `docker compose logs -f`. Остановка: `docker compose down`. При первой сборке скачиваются PyTorch и веса модели; нужны интернет и несколько гигабайт свободного места.

Для публичного использования настройте домен и HTTPS через обратный прокси, например Caddy или Nginx с TLS-сертификатом. Прокси должен разрешать загрузку файлов размером не менее 100 МБ плюс служебные данные multipart и не обрывать медленные загрузки. Если прокси запущен на том же сервере, можно ограничить публикацию Docker-порта адресом `127.0.0.1:8000:8000` в `compose.yaml` и проксировать на него запросы. Создайте QR-код из итогового HTTPS-адреса сайта любым удобным генератором; проверьте его с телефона вне сети сервера.

## Ноутбук в Colab

В проекте лежит `yolo26_colab.ipynb`. До настройки ссылки сайт предлагает скачать файл: затем его можно открыть через Google Colab → «Файл» → «Загрузить блокнот». Чтобы ссылка вела непосредственно в Colab, опубликуйте ноутбук в общедоступном репозитории GitHub и укажите в `.env`:

```text
COLAB_URL=https://colab.research.google.com/github/USER/REPO/blob/main/yolo26_colab.ipynb
```

Замените `USER`, `REPO` и путь на свои; проверьте ссылку в приватном окне браузера. Примените изменение: `docker compose up -d`.

## Настройки

- `IMAGE_WORKERS=2`, `VIDEO_WORKERS=1`: число процессов для каждого типа; у каждого своя копия модели. Для дополнительных процессов нужны память и процессорные ядра.
- `MODEL_THREADS=1`: число потоков PyTorch на процесс. При изменении настройте под число ядер сервера.
- `MAX_QUEUE=60`: максимум ожидающих и обрабатываемых заданий вместе. При заполнении новые задания получают ошибку и могут быть отправлены повторно.
- `RESULT_TTL_SECONDS=3600`: время хранения после завершения; очистка запускается каждую минуту. Входные файлы, результаты и сообщения об ошибках удаляются вместе. После перезапуска выполнявшиеся задания возвращаются в очередь.
- `COLAB_URL`: публичная ссылка на ноутбук; если не задана, доступно скачивание файла.

Допустимые форматы: JPG, PNG, WebP до 20 МиБ и MP4, MOV, WebM, AVI, MKV до 100 МиБ. Изображения ограничены 40 мегапикселями. Время для изображения включает обработку и сохранение; среднее время кадра видео включает декодирование и кодирование. Видео обрабатывается целиком, поэтому длинный ролик может занять много времени. Для ограничения нагрузки следите за свободным местом на диске: выходной файл может быть больше исходного. Данные хранятся в Docker-томе `yolo-data`; `docker compose down -v` безвозвратно удаляет его.
